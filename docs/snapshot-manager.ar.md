# Snapshot Manager — واجهة إدارة اللقطات

تشغيل `HUMAIN.CoordinationTracker.exe` بدون معاملات يفتح واجهة Windows. نفس مجلد البيانات ونفس حسابات الداشبورد مستخدمة؛ لا يلزم نقل بيانات المشروع.

## استيراد لقطة

1. صدّر Navisworks بصيغة XML مع اختيار All tests (separate)، بنفس النطاق وبكل الحالات.
2. اختر Browse XML folder ثم حدد التاريخ والوقت الفعليين للقطة.
3. اضغط Preview import. المعاينة تعرض الاختبارات والسجلات الغائبة والتنبيهات، ثم الرصيد وحركات التاريخ قبل التغيير وبعده.
4. بعد مراجعتها اضغط Approve & apply preview.
5. انتظر رسالة النجاح ثم اعمل Refresh في Power BI. لا تبدأ Refresh أثناء التطبيق.

المعاينة لا تغير اللقطات أو ملفات Power BI الفعلية. فشل قراءة أي XML، أو غياب GUID، أو تكراره، أو عدم وجود اختبار واحد في الملف يمنع الاستيراد كله. الاختبار الذي يحتوي صفر كلاشات مقبول. تنبيهات الجودة الأخرى تظهر للمراجعة قبل الاعتماد ولا تمنع قبول تغيير نطاق مقصود.

## استبدال لقطة بعينها

اختر الصف، فعّل Replace selected snapshot، اختر فولدر التصدير المصحح، واكتب السبب. المعاينة تستخدم **تاريخ ووقت الصف المختار** حتى لو كان حقل الوقت مختلفًا. الاستبدال يحتفظ بحالة الاستبعاد إذا كانت اللقطة مستبعدة؛ استعدها بشكل منفصل عند الرغبة. توجد نسخة احتياطية قبل التطبيق.

## استبعاد واستعادة

اختر اللقطة واكتب السبب ثم Preview exclusion أو Preview restore. راجع النتيجة قبل الاعتماد. الاستبعاد يحتفظ بملفات اللقطة الأصلية ويضيف علامة استبعاد؛ Restore يزيل العلامة ويعيد إدخالها في الحسابات.

- استبعاد الأولى يجعل أول لقطة نشطة تالية خط الأساس، وقد يغير الأعمار وFirstSeen.
- استبعاد لقطة وسطية يقارن السابقة بالتالية مباشرة؛ الحركات الوسيطة قد تختفي.
- استبعاد الأخيرة يعيد الرصيد الحالي إلى آخر لقطة نشطة متبقية.
- استبعاد كل اللقطات ينتج ملفات بلا بيانات حالية؛ لا يوجد حذف نهائي من الواجهة.

بعد تطبيق التغيير اضغط Reload list لتحديث القائمة. تغيير المدخلات أو تحديد صف آخر يلغي صلاحية المعاينة السابقة. إذا تغير تاريخ المشروع من نافذة أخرى بعد المعاينة، يرفض التطبيق اعتمادها ويطلب معاينة جديدة.

## النسخ الاحتياطية واستعادة التشغيل

- Backup now يحفظ نسخة يدوية.
- كل تطبيق لتغيير أو إعادة بناء ينشئ نسخة تلقائية تحت `Backups` من Snapshots وPowerBI وclash_history.csv.
- Open backups يفتح مكان النسخ. لا يوجد زر لاستعادة مشروع كامل من Backup في هذه النسخة؛ Preview restore خاص باللقطات المستبعدة.
- تتولد النتائج في مساحة مؤقتة قبل نشرها. عند فشل النشر يحاول التطبيق إرجاع المجلدات السابقة. إذا انقطع التطبيق أثناء النشر، تستكمل عملية الرجوع في التشغيل التالي قبل أي عمل جديد.
- لا يمكن نشر عدة مجلدات كعملية ذرية واحدة؛ لذلك يجب الانتظار حتى النجاح قبل Refresh في Power BI. إذا تعذر الرجوع بسبب ملف مقفول، أغلق البرنامج الذي يقفل الملفات ثم شغّل Tracker مجددًا. لا تحذف سجل الاستعادة يدويًا.
- ملف `operations.log` يسجل العمليات المكتملة وأسبابها ومسار نسختها الاحتياطية. ليس نظام تدقيق متعدد المستخدمين.
- يحتفظ التطبيق بالنسخ الاحتياطية دون حذف تلقائي؛ راقب المساحة. يتم تنظيف معاينات العمليات والعمليات الناجحة، وقد تبقى مجلدات عمليات فاشلة للتشخيص.

## أوامر الصيانة

```text
HUMAIN.CoordinationTracker.exe --console
HUMAIN.CoordinationTracker.exe --gui --data-root C:\path\to\project
HUMAIN.CoordinationTracker.exe --rebuild
HUMAIN.CoordinationTracker.exe --self-test
```

الوضع التفاعلي القديم متاح بـ --console. إعادة البناء تمر بنفس آلية النسخ الاحتياطي والنشر القابل للاستعادة. الإصدارات القديمة من البرنامج لا تعرف علامة الاستبعاد؛ استخدم هذا الإصدار لكل عمليات الاستيراد وإعادة البناء بعد بدء استخدام الاستبعاد.

## التحقق

اجتاز الإصدار 204 تحققًا لمنطق الحالات، و11 للجودة، و22 لإدارة اللقطات. تشمل اختبارات الإدارة المعاينة دون تعديل، الاستبعاد والاستعادة، تغير خط الأساس وآخر لقطة، المشروع الفارغ، رفض المعاينة القديمة، منع الكتابة المتزامنة، فشل البناء والنشر، واستعادة نشر منقطع، ورفض ملفات XML التالفة والمكررة وغير المناسبة. اختبارات الإدارة تستخدم مجلدات مؤقتة مستقلة.

## تحديث الواجهة 1.3

أصبحت الأزرار مباشرة بالعربية: استيراد لقطة، استبعاد اللقطة، استعادة اللقطة، تحديث بيانات الداشبورد. بعد اختيار العملية تظهر مراجعة التأثير تلقائيًا مع زر تأكيد باسم العملية وزر رجوع بدون تغيير. أزيل زر الاعتماد المنفصل، وتُحدّث القائمة تلقائيًا بعد النجاح. منطق الحساب والنسخ الاحتياطي لم يتغير. أسماء Preview في الشرح أعلاه تخص الواجهة السابقة.
